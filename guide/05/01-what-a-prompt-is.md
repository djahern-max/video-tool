# What a prompt is

<!-- index: 13#1, 13#2, 13#6; 4#8 -->

This lesson is about the text a CPA types into ChatGPT, and how to write
it so that what comes back is worth the time spent checking it. Lesson 1
was about what the model gets wrong and lesson 2 about how an account is
set up; this one is about the request itself.

## The vendor's definition

OpenAI's help-center page on prompt engineering says that a prompt for a
large language model is a text input that initiates a conversation or
triggers a response from the model, and that it can take other forms,
such as an image or audio. The same page defines prompt engineering as
the process of designing and optimizing input prompts to effectively
guide a language model's responses. Two words in that definition carry
the rest of this lesson. *Designing* says a prompt is written, not just
typed; *optimizing* says it is revised. Sections 02 and 03 are about the
first, and section 04 is about the second.

## Only as good as the prompt

The CPA.com Generative AI Toolkit, a 2023 introduction to generative AI
written for accounting and finance professionals, states the same point
from the user's side: generative AI is only as good as the prompt that
drives it. That is the toolkit's sentence, and the rest of this lesson
follows from it. The prompt is the part of the exchange the user writes,
and so it is the part the user can improve.

## Where the advice comes from

OpenAI's page adds one note about its own guidance. It points to longer
prompting guides, and says that though some of them reference OpenAI's
API, the recommendations themselves are relevant for ChatGPT. Those
longer guides are not part of this lesson. What this lesson takes from
the page is the three general practices it lists — be clear and specific,
refine iteratively, and set the tone — and what it takes from the toolkit
is two more: give the model examples, and ask it for verbatim excerpts.
Section 06 then turns to a limit that none of the five practices removes:
how much text one request can hold.
