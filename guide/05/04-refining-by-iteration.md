# Refining by iteration

<!-- index: 13#4, 13#2 (and the sentence that follows 13#4 on the page, J1) -->

The second of OpenAI's practices is about what happens after the first
response. The page says to start with an initial prompt, review the
response, and refine the prompt based on the output. It then names three
kinds of refinement: adjust the wording, add more context, or simplify
the request, as needed to improve the results.

## Three moves

Each of the three is a change to the input, not a complaint about the
output. *Adjust the wording* is section 02's clarity, applied after
seeing what the first wording produced. *Add more context* is section
02's third part: if the response would suit a general reader and not the
actual one, the actual reader goes into the prompt. *Simplify the
request* runs the other way: a prompt that asked for several things at
once asks for fewer.

Suppose the first prompt asked for a summary of a document and the
response summarised a part of it the reader did not care about. The
second prompt names the part. Suppose instead that the response was in
the wrong register. The second prompt names the tone, as section 03
described. In each case the response is not argued with; the prompt is
changed.

## Review is the middle step

The page's sequence has three steps, and the middle one, review the
response, is lesson 4's subject. Which of the three moves to make depends
on what was wrong with the response, and finding that out is what the
review is for. A prompt refined on the strength of a response that has
not been read closely is refined toward whatever the response happened to
be.

## Iteration is in the definition

Section 01 quoted the page's definition of prompt engineering: designing
*and optimizing* input prompts. Optimizing is this section. A prompt that
is right the first time is not the case the page describes; the page
describes a first prompt, a response, and a second prompt, and it puts no
number on how many rounds that takes.
